# 私户网银付款风险控制方案

> 适用前提：仍以私人银行卡 + 电脑端网银付款为主；**无法开通双 U 盾**。  
> 目标：在单人可技术性点付的前提下，用「人控 + 单证 + 分档 + 事后复核」把错付、错户、户名不符退汇降到可控。  
> 数据背景：与《资金支付体系优化方案报告》一致——客单价高、私卡暴露大，大额应尽量控流程。

---

## 一、方案原则（没有双 U 盾时靠什么）

银行侧做不到「两人才能点支付」，财务侧就要做到：

1. **支付前必须有第二人书面确认**（确认的是「付谁、付多少、账号对不对」）。  
2. **网银操作人不得独自完成「填单 + 核对 + 点击」全链路**。  
3. **大额先验证再付全款**（试打 / 户名校验 / 对方书面确认）。  
4. **一切改账号视为新付款**，禁止口头改号后直接付。  
5. **付完当日对回单**，错付有追责闭环。

一句话：**双 U 盾管的是“能不能点”；本方案管的是“没确认就不允许点”。**

---

## 二、角色分工（建议最少 3 个角色，可兼职但关键动作不能同一人）

| 角色 | 谁来当 | 职责 | 禁止事项 |
|------|--------|------|----------|
| 申请人 | 业务 / 采购 | 发起付款、提供收款信息与合同 | 不得自己点网银支付 |
| 制单复核人 | 财务 A | 建档、核对白名单、制作《付款指令单》 | 不得独自点击支付（若其持有 U 盾，须等指令单签满） |
| 支付执行人 | 财务 B（持 U 盾） | 仅按已签批的指令单录入并支付 | 不得自行改账号/金额；指令单缺签不得付 |
| 抽检人（可选） | 财务负责人 / 店长 | ≥50 万抽检或必审 | — |

> 若财务只有 2 人：申请人为业务；财务 A 制单+初核；财务 B 持盾支付前，必须把「网银录入截图」发回财务 A 口头/微信确认「一致」后再点支付。  
> **持盾人可以是最终点击的人，但不能是唯一核对的人。**

---

## 三、总流程（私户付款标准链路）

```
业务申请 → 收款信息核验/白名单 → 财务制《付款指令单》
    → 第二人复核签字 →（大额）试打或对方确认
    → 持盾人按单录入 → 录入截图二次确认 → 点击支付
    → 回单粘贴归档 → 当日对账
```

### 步骤说明

**1）付款申请（业务）**  
填写：收款户名、账号、开户行、金额、事由、合同/订单号、对方联系方式。  
附件：合同或确认记录、收款信息截图（须与填写一致）。

**2）收款方管理（财务）**  
- 首次合作：录入《收款白名单》，核对户名与账号来源。  
- 已在白名单且信息未变：可走快捷通道。  
- **账号/户名有任何变更**：走「变更单」，视同新供应商，重新核验。

**3）制作《付款指令单》（财务 A）**  
指令单是支付的唯一依据，字段固定：

- 付款日期、付款卡（哪张私卡）  
- 收款户名、账号、开户行（从白名单带出，禁止手抄后不核对）  
- 金额（大写 + 小写）  
- 事由 / 关联单号  
- 风险提示勾选（是否新账户、是否异地、是否 ≥50 万）  
- 签字栏：申请人、制单人、复核人、（大额）负责人  

**4）第二人复核（财务 B 或负责人）**  
复核清单（必须逐项勾）：

- [ ] 户名、账号、开户行与白名单一致  
- [ ] 与业务附件截图一致  
- [ ] 金额与合同/审批一致  
- [ ] 无重复付款（查当日/近 3 日已付）  
- [ ] 大额已完成试打或对方书面确认  

缺任何一项 → **不得进入网银**。

**5）网银执行（持盾人）——替代双 U 盾的关键动作**  

1. 打开网银，**只照指令单录入**，不得凭聊天记录临时改号。  
2. 录入完成后，在点击「确认支付/提交」前：  
   - 截图（含户名、账号、金额）；  
   - 发给复核人；  
   - 复核人回复固定话术：**「一致，可付」**（或指令单编号 + 可付）。  
3. 收到确认后，**60 秒内完成支付**；若又改动任何字段，须重新截图确认。  
4. 支付成功后下载回单，回传申请人与复核人。

**6）事后闭环**  
- 回单粘贴到指令单背面或电子归档，三单一致：申请、指令、回单。  
- 退汇：原因归档；修正收款信息后从头走全流程，禁止「退回后直接改号再付」。  
- 每日日终：私卡流水 vs 指令单清单勾对。

## 四、金额分档控制（建议值，可按公司调整）

| 档位 | 金额 | 必做控制 |
|------|------|----------|
| 普通 | ＜10 万 | 申请 + 指令单双签 + 录入截图确认后支付 |
| 关注 | 10 万～50 万（不含） | 同上 + 业务负责人确认收款信息 |
| 大额 | **50 万～100 万（不含）** | 同上 + **试打验证**或银行户名校验 + 财务负责人签批 |
| 特大 | **≥100 万** | 同上 + 对方书面/录音确认账号 + 可拆笔（如无业务障碍）+ 支付前三人确认（申请、复核、负责人） |

### 试打规则（大额强烈建议）

- 先付 **1～100 元**（或银行支持的最小额）到目标账户。  
- 对方确认到账且户名无误后，再付尾款。  
- 试打与尾款必须两张指令单或一张指令单分两行，均需复核。  
- 若银行支持「收款户名校验」且校验通过，可替代试打（须在指令单注明校验结果截图）。

## 五、防错专项动作（针对你们现有痛点）

### 1. 防账号填错

- 白名单复制粘贴，禁止手工敲账号。  
- 录入后用「读数法」：复核人看着指令单，持盾人读出账号后四位与户名，两人交叉确认。

### 2. 防户名与账号不符导致退汇

- 新账户、变更账户：先试打或户名校验。  
- 指令单增加勾选项：「已核验户名一致」。

### 3. 防打错账户 / 张冠李戴

- 一笔指令单只对应一个收款账户。  
- 连续付多笔时，每笔单独截图确认，禁止「一口气录完再一起点」。  
- 支付队列按指令单编号顺序，付完一张勾销一张。

### 4. 防单人冲动支付（无双 U 盾的补偿）

- **无「可付」回复，不得点击支付**——写进制度并纳入考核。  
- 网银操作尽量双人在场（一人录入、一人看着指令单）。  
- 聊天工具设付款专用群：只传指令单 PDF/照片与「一致可付」，方便留痕审计。

## 六、《付款指令单》最小字段（可直接做成表格）

1. 指令单编号（日期+序号）  
2. 付款私卡（持卡人/银行/后四位）  
3. 收款户名 / 账号 / 开户行  
4. 是否白名单：是 / 新户 / 变更户  
5. 金额（小写 + 大写）  
6. 事由与关联单号  
7. 分档：普通 / 关注 / 大额 / 特大  
8. 已做：试打□ 户名校验□ 对方确认□  
9. 签字：申请人 / 制单 / 复核 / 负责人  
10. 支付栏：支付时间、回单号、执行人签、复核「可付」记录（消息截图编号）

---

## 七、禁止事项（红线）

1. 无指令单或指令单缺复核签字付款。  
2. 凭微信口头「账号改成这个」直接改网银支付。  
3. 持盾人独自完成核对并支付（无第二人确认）。  
4. 大额跳过试打/校验且无负责人特批。  
5. 退汇后不重新制单、直接改号再付。  
6. 用私人聊天记录替代白名单与指令单归档。

---

## 八、与支付结构的衔接（报告口径）

在仍保留私卡的前提下（报告方案 B 私卡约 14.19%）：

- 能走第三方/对公的大额，优先分流，减少百万级私卡单笔。  
- 必须走私卡的：严格执行本方案分档与截图确认。  
- 私卡用途尽量限于：报告所述小额绿色单、收表周转、平台故障应急；**常态百万级采购不应作为私卡默认路径。**

## 九、落地一周安排

| 天 | 动作 |
|----|------|
| Day 1 | 定角色：谁制单、谁复核、谁持盾；建付款专用确认群 |
| Day 2 | 上白名单表 + 指令单模板；旧收款方集中补录 |
| Day 3 | 试跑：所有私卡付款强制指令单 + 截图确认 |
| Day 4 | ≥50 万启用试打；明确特批谁有权签 |
| Day 5 | 日终对账表上线；抽检 3 笔历史易错场景做演练 |
| Day 6–7 | 修订阈值；把「无确认付款」写入奖惩 |

## 十、有效性说明（预期能挡住什么）

| 风险 | 本方案如何挡 |
|------|----------------|
| 账号填错 | 白名单粘贴 + 读数交叉 + 截图二次确认 |
| 户名不符退汇 | 新户/变更户试打或户名校验 |
| 打错人 | 一单一户 + 逐笔确认 + 禁止连续盲付 |
| 单人失误/舞弊 | 无第二人「可付」不得点；事后回单与流水对账 |

> 局限：无法从银行系统层锁死单人支付；若持盾人恶意绕过流程，需靠监控、对账与追责约束。因此 **「可付」留痕 + 日终对账 + 抽检** 必须同时执行，不能只做前半段。
